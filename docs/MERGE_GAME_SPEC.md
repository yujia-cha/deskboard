# Merge 게임 — 게임 시스템 명세 (초기 설정)

> 구조·네트워크 설계는 [MERGE_GAME.md](MERGE_GAME.md). 이 문서는 **게임 규칙과 콘텐츠**만 다룬다.
>
> **이 문서는 출발점이다.** 여기서 틀을 잡고 조금씩 더해 간다 — 그래서 규칙은 작게, 늘릴 자리는
> 넓게 잡았다 (§17 "더해 가는 법").
>
> **고치는 법**
> - 규칙에는 번호가 있다 (`B-3`, `O-5` …). "O-5 를 이렇게 바꿔 줘" 처럼 번호로 말하거나 이 파일을 직접 고친다.
> - 숫자는 본문에 `〔키〕` 로 표시하고 **§16 조정값 표**에 모았다. 표의 키는 그대로
>   `resources/merge-economy.json` 의 키가 된다 — 숫자를 바꾸는 데 코드를 고칠 필요가 없게.
> - ✏️ 표시는 특히 취향이 갈릴 만한 곳이다.

## 1. 재화와 점수

| | 얻는 곳 | 쓰는 곳 |
|---|---|---|
| **⚡ 에너지** (유일한 재화) | 할 일 완료 (§11) · 시간 회복 (§12) · 클리커 (§13) · 아이템 판매 환급 (M-3) | 생산 · 상자 바로 열기 · 보관함 늘리기 · 주문 교체 |
| ⭐ 별 (점수) | 주문 전달 | 쓰지 않는다. 쌓이면 레벨이 오르고, 친구에게 공유된다 |

- **C-1** 에너지 외의 재화(코인·보석)는 없다. 무엇이든 값을 매겨야 하면 ⚡ 로 매긴다.
- **C-2** 과금·광고는 없다.
- **C-3** ⚡ 는 음수가 될 수 있다 (할 일 체크를 풀었을 때만, E-5). 음수면 ⚡ 를 쓰는 조작만 멈춘다.
- **C-4** ⚡ 에 **보관 상한은 없다.** (시간 회복에만 멈추는 선이 있다 — E-3)

## 2. 보드와 칸

- **B-1** 보드는 가로 7 × 세로 9 = 63칸 〔board.w〕〔board.h〕. 크기는 고정이다.
- **B-2** 칸마다 상태가 하나다:

| 상태 | 표시 | 내용물 | 끌 수 있나 | 놓을 수 있나 |
|---|---|---|---|---|
| `empty` 빈 칸 | 옅은 바탕 | 없음 | — | ✓ (이동) |
| `free` | 아이템 | 보임 | ✓ | ✓ (합성·교환) |
| `web` 🕸 거미줄 | 아이템 + 반투명 거미줄 | 보임 | ✗ | 같은 아이템만 (§6) |
| `box` 📦 상자 | 상자 | **숨김** | ✗ | ✗ |

- **B-3** "이웃" 은 **상하좌우 4칸**이다. 대각선은 이웃이 아니다.
- **B-4** 위젯이 여러 개 떠 있어도 보드는 하나다 (모두 같은 보드를 보여 준다).
- **B-5** 상자·거미줄의 그림도 꾸미기 대상이다 (§14).

## 3. 아이템과 계열

- **I-1** 모든 아이템은 `(계열 id, 레벨)` 이다. 같은 계열·같은 레벨 둘을 합치면 다음 레벨 하나가 된다.
- **I-2** 레벨 n 의 **가치** `u(n) = 2^(n-1)` — "Lv1 몇 개분인가" = "⚡ 몇 개를 들였나". 보상·환급이 모두 이 값에서 나온다.
- **I-3** 계열의 최고 레벨은 더 합칠 수 없다. 주문에 쓰거나 판다.
- **I-4** 해금되지 않은 계열의 아이템도 (상자에서 나오면) 합칠 수 있다. 다만 생산기가 내지 않고 주문에도 나오지 않는다.
- **I-5** **계열의 "규칙"과 "외형"은 따로 저장한다.** 규칙 = id·레벨 수·해금 레벨·어느 생산기가 내는지.
  외형 = 계열 이름, 레벨마다 이름과 그림. 외형은 언제든 바꿔도 보드가 깨지지 않는다 (보드는 id·레벨만 기억한다). §14.

## 4. 조작

- **M-1 끌어 놓기** — `free` 아이템을 끌어 다른 칸에 놓는다:

| 놓은 칸 | 결과 |
|---|---|
| 빈 칸 | 이동 |
| 같은 아이템 (`free`) | **합성** — 놓은 칸에 다음 레벨, 끈 칸은 빈 칸 |
| 같은 아이템 (`web`) | **합성 + 거미줄 풀림** (W-2) |
| 다른 아이템 (`free`) | 자리 교환 |
| 다른 아이템 (`web`), 상자, 보드 밖 | 아무 일 없음 (제자리로) |
| 보관함 칸 | 보관 (§8) |

- **M-2 클릭** — 아이템을 고른다. 바닥줄에 이름·레벨·"합치면 무엇이 되는지"·판매 환급량이 뜬다.
  생산기 클릭 = **생산**(§5), 🎁 클릭 = **꺼내기**(§7), 상자 클릭 = "⚡ 〔box.openCost〕 로 열기" 확인.
- **M-3 판매** — 고른 아이템의 [팔기] → ⚡ `floor(u(n) × 〔sell.refund = 0.5〕)` 환급.
  Lv1 은 0 이라 버튼이 [버리기] 가 된다. 들인 것보다 늘 덜 돌려받으므로 생산→판매로 ⚡ 를 불릴 수 없다.
  Lv5 이상은 한 번 더 묻는다 〔sell.confirmFromLevel〕.
- **M-4** 되돌리기(undo)는 없다.
- **M-5** 편집 모드(대시보드의 카드 배치 모드)에서는 보드가 입력을 받지 않는다.

## 5. 생산기

- **G-1** 생산기를 클릭하면 ⚡ 〔gen.cost = 1〕 를 쓰고 아이템 하나가 나온다.
- **G-2** 나오는 자리: 생산기에서 **가장 가까운 빈 칸** (맨해튼 거리, 같으면 위쪽 → 왼쪽 우선).
- **G-3** 빈 칸이 없으면 ⚡ 를 쓰지 않고 "보드가 가득 찼어요".
- **G-4** ⚡ 가 모자라면 생산되지 않고, ⚡ 표시가 흔들리며 클리커(§13)가 강조된다.
- **G-5 드롭 표** — 생산기 레벨별로 나오는 아이템 레벨 〔gen.dropTable〕 ✏️:

| 생산기 레벨 | Lv1 | Lv2 | Lv3 |
|---|---|---|---|
| 1 | 100% | — | — |
| 2 | 85% | 15% | — |
| 3 | 70% | 30% | — |
| 4 | 55% | 40% | 5% |
| 5 | 40% | 50% | 10% |

  계열은 그 생산기가 내는 계열 중 **해금됐고 숨기지 않은 것**에서 고르게 고른다.
- **G-6** 생산기에 쿨다운·충전 횟수는 없다. 제한은 ⚡ 뿐이다.

## 6. 상자와 거미줄

- **W-1 상자 열림** — 어느 칸에서 **합성**이 일어나면 그 칸의 이웃 상자가 모두 열려 `web` 이 된다.
  이동·교환·생산으로는 열리지 않는다.
- **W-2 거미줄 풀기** — `web` 아이템 위에 같은 아이템을 놓으면 합성되어 다음 레벨의 `free` 가 된다.
  이것도 합성이므로 W-1 이 또 일어나 바깥쪽으로 보드가 열려 나간다.
- **W-3** 거미줄에 걸린 것이 최고 레벨이면 이웃에서 합성이 일어날 때 그냥 `free` 로 풀린다 (막힌 칸 방지).
- **W-4 바로 열기** — 상자를 클릭해 ⚡ 〔box.openCost = 5〕 를 내면 바로 `web` 이 된다.
- **W-5** 상자는 다시 생기지 않는다. 다 열면 63칸 모두 작업 공간이다.

## 7. 특수 아이템

- **S-1 🎁 선물** — 클릭할 때마다 안에 든 아이템이 하나씩 G-2 자리로 나온다 (⚡ 안 씀). 다 나오면 사라진다.
  남은 개수가 모서리에 보인다.
- **S-2** 🎁 는 합칠 수도 팔 수도 없다. 보관함에는 넣을 수 있다.
- **S-3** 🎁 를 얻는 곳: 레벨업(§10), 주민 친밀도(O-9), 시작 보드의 상자.
- **S-4** 특수 아이템은 종류를 늘려 갈 자리다 (§17). 지금은 🎁 하나.

## 8. 보관함

- **V-1** 보드 아래 한 줄. 처음 4칸 〔inv.start〕, ⚡ 로 늘린다: 20 → 40 → 80 → 160 … 〔inv.costs〕. 최대 12칸 〔inv.max〕.
- **V-2** 아무 `free` 아이템(생산기·🎁 포함)을 끌어 넣고 끌어 꺼낸다. 보관함 안에서는 합쳐지지 않는다.
- **V-3** 주문 전달 시 보관함의 아이템도 쓴다 (O-5).

### 9.1 기본 주민 (초기값 — 이름·그림·좋아하는 계열 모두 바꿀 수 있다) ✏️

### 9.2 주문

- **O-1** 주문 칸은 3개 〔order.slots〕, Lv5 부터 4개 〔order.slotsAt5〕. 입주한 주민이 칸보다 많으면 돌아가며 주문한다.
- **O-2** 주문 하나 = 아이템 1종, Lv3 부터 30% 확률로 2종 〔order.twoItemChance〕. 종마다 1개.
  요구 아이템은 그 주민이 좋아하는 계열 중 **해금됐고 숨기지 않은 것**에서 고른다.
- **O-3 요구 레벨** — 플레이어 레벨 L 일 때 `최고 = min(계열 최고, 2 + floor(L/2))`, `최저 = max(2, 최고 - 2)`,
  그 사이에서 고르게. 예: L1 → Lv2 만, L4 → Lv2~4, L10 → Lv5~7 〔order.levelBase〕〔order.levelSpan〕 ✏️
- **O-4** 보드나 보관함에 요구한 아이템이 `free` 로 있으면 주문 칩과 그 칸에 ✔ 가 붙는다.
  2종 주문은 둘 다 있어야 [전달] 이 켜진다. 거미줄에 걸린 것은 세지 않는다.
- **O-5 전달** — 보관함 먼저, 그다음 보드의 위→아래, 왼쪽→오른쪽 순으로 가져간다.
- **O-6 보상** — `V = Σ u(레벨)` 일 때 ⭐ `max(1, round(V × 〔order.starPerValue = 0.5〕))`.
  ⚡ 보상은 기본 0 〔order.energyPerValue = 0〕 ✏️ — 켜면 "주문이 다음 생산의 밑천" 이 되는 순환이 생긴다.
  예: Lv3 하나(V=4) → ⭐2. Lv6 + Lv5 (V=48) → ⭐24.
- **O-7** 전달하면 그 칸에 곧바로 새 주문이 온다.
- **O-8 교체** — 주문 칩의 🔄 → ⚡ 〔order.rerollCost = 2〕 로 같은 주민의 다른 주문으로.
- **O-9 친밀도** — 주민마다 전달 횟수를 센다. 5·15·30·50번째에 🎁 (좋아하는 계열 Lv3·Lv4·Lv5·Lv6 ×1) 〔resident.heartMilestones〕.

| 3 | 25 | `cook`, 🐱, 2종 주문 시작 |
| 4 | 45 | 🧰 Lv1 하나 더 |
| 5 | 70 | `tools`, 🐶, 주문 칸 4개, 보관함 +1 |
| 6 | 100 | 🛒 Lv1 하나 더 |
| 7 | 140 | `sew`, 🪡, 🦊 |
| 8 | 190 | 🎁 (아무 계열 Lv4 ×2) |
| 9 | 250 | 🐻 |

| 11+ | 이전 + 80 | 짝수 레벨마다 🎁 (Lv5 ×1) |

- **L-2** 받은 생산기·🎁 는 G-2 자리로 나온다. 빈 칸이 없으면 보관함, 그것도 차 있으면 "받을 선물" 줄에 쌓인다 — 레벨업 보상을 잃는 일은 없다.
- **L-3** 레벨은 내려가지 않는다.
- **L-4** 사용자가 만든 계열(§14 Z-5)은 만들 때 해금 레벨을 고른다 (기본: 지금 레벨 = 바로 해금).

## 11. 할 일

- **T-1** 할 일 = `내용 · 주기(일간/주간) · 크기(작음/보통/큼) · 목표 횟수 · 공개 여부`.
- **T-2 주기**
  - 일간: 날마다 새로 시작 (기간 키 `2026-10-07`). 주간: 월요일에 새로 시작 (기간 키 `2026-W41`).
  - **하루의 시작 시각** 〔설정 dayStartHour, 0~6시, 기본 0〕 — 4로 두면 새벽 3시에 한 일도 "어제" 다.
  - 기간이 바뀌면 체크가 저절로 비어 보인다.
- **T-3 목표 횟수** (주간 전용, 기본 1) — "헬스장 3번" 이면 누를 때마다 1/3 → 2/3 → 3/3, **채운 순간** ⚡.
- **T-4 개수 제한 없음.**
- **T-5** 내용·크기·목표 횟수는 언제든 고친다. 이미 받은 ⚡ 는 그대로 두고, 바뀐 값은 다음 체크부터 쓴다.
  지우면 목록에서 사라지지만 받은 ⚡ 와 완료 기록은 남는다.
- **T-6** 지금 기간의 할 일만 체크·해제한다. 지난 기간은 볼 수만 있다 ✏️
- **T-7 공개 여부** — 끄면(🔒) 친구에게 내용 없이 "비공개 할 일 ☑" 로만 보인다. 새 할 일의 기본값은 설정 〔설정 sharedDefault, 기본 공개〕.
- **T-8 순서** — 손잡이(⠿)로 끌어 바꾼다.
- **T-9** **방금 만든 할 일을 바로 체크해도 ⚡ 를 준다.** 그냥 에너지가 필요하면 클리커(§13)로 얻으면 되니,
  할 일 쪽에 남용 방지 장치를 두지 않는다.

## 12. 에너지

- **E-1 할 일 지급량** ✏️

| 크기 | 일간 | 주간 |
|---|---|---|
| 작음 | 10⚡ | 30⚡ |
| 보통 | 20⚡ | 60⚡ |
| 큼 | 30⚡ | 90⚡ |

  〔energy.daily = [10,20,30]〕〔energy.weekly = [30,60,90]〕. **지급 상한 없음.**
- **E-2** 체크하는 순간 들어온다. 같은 할 일을 같은 기간에 두 번 받지는 않는다 (빠르게 두 번 눌러도 한 번).
- **E-3 시간 회복** — 〔regen.intervalSec = 120〕 초마다 +1⚡, **⚡ 가 〔regen.cap = 100〕 미만일 때만**.
  할 일·클리커로는 100 을 넘게 모을 수 있다 — 시간 회복만 거기서 멈춘다 (켜 두기만 해도 끝없이 쌓이면
  할 일을 할 이유가 사라지므로). 머리줄에 "다음 +1 까지 01:23" 을 보인다 (스크린샷의 `00:03` 자리).
  앱이 꺼져 있던 동안의 시간도 센다 (다시 켤 때 몰아서). ✏️
- **E-4 시작 에너지** 100⚡ 〔energy.start〕.
- **E-5 체크 해제** — 받은 만큼 되돌린다 (보너스가 깨지면 보너스도). 이미 써 버렸으면 ⚡ 가 음수가 된다 (C-3).
- **E-6 보너스**
  - 오늘 일간 할 일 모두 완료: +20⚡ 〔energy.allClearDaily〕
  - 이번 주 주간 할 일 모두 완료: +50⚡ 〔energy.allClearWeekly〕
  - 연속 달성 (모두 완료한 날이 이어진 날수 × 5⚡, 최대 +30⚡) 〔energy.streakPerDay〕〔energy.streakMax〕 — 모두 완료 보너스와 함께.
  - 그날 일간 할 일이 하나도 없으면 연속이 끊기지도 늘지도 않는다.
- **E-7** 모든 증감은 기록에 남고 "에너지 기록" 에서 볼 수 있다 (생산·회복·클리커는 하루 단위로 묶어 `-37 생산 ×37`).

**대략의 감각**: 회복만으로 하루 최대 720⚡(2분에 1) — 단, 100 에서 멈추므로 실제로는 "비워 두면 3시간 20분에 100 이 찬다".
할 일 4~5개(≈ 80⚡) + 모두 완료 20⚡ ≈ 100⚡. 초반 주문은 4~8⚡, 후반 Lv5 주문은 16⚡.

## 13. 클리커

보드 **옆**에 붙은 작은 미니게임. 할 일도 회복도 기다리기 싫을 때 ⚡ 를 그냥 얻는 곳이다.

- **K-1** 버튼 하나 (기본 그림 🐹 — 꾸미기 대상, §14). 누를 때마다 둘레의 진행 고리가 1/N 씩 찬다.
  N 번 누르면 +1⚡ 〔clicker.clicksPerEnergy = 20〕, 고리가 비고 ⚡ 가 머리줄로 날아간다.
- **K-2** 마우스 클릭만 센다. 키보드(스페이스·엔터)는 세지 않는다 — 키를 누르고 있으면 자동 반복으로 끝없이 눌린다.
- **K-3** 속도 제한·하루 상한 없음.
- **K-4** 남은 클릭(고리에 찬 만큼)은 저장된다 — 끄고 켜도 이어진다.
- **K-5** 위치: 위젯이 충분히 넓으면(폭 ≥ 높이 × 0.75) 보드 오른쪽 세로 줄, 좁으면 보드 아래 가로 줄.
- 늘려 갈 자리 (§17): 콤보, 업그레이드(⚡ 를 써서 N 을 줄이기), 가끔 나오는 황금 클릭 등.

## 14. 외형 꾸미기

"도감" 탭에서 아이템 계열·생산기·주민·클리커·상자/거미줄의 **이름과 그림**을 바꾼다.

- **Z-1 그림의 종류** — 셋 중 하나:
  - 이모지 한 글자 (입력란에 붙여넣기)
  - 이미지 파일 (PNG/JPG/BMP) — 불러오면 128×128 정사각형으로 줄여(비율 유지, 남는 곳 투명) 앱 데이터 폴더에 복사해 둔다.
    원본 파일을 지워도 그대로 보인다.
  - 글자 1~2자 (색은 테마 강조색)
- **Z-2 바꿀 수 있는 것**

| 대상 | 이름 | 그림 | 규칙 |
|---|---|---|---|
| 계열 | 계열 이름, 레벨마다 이름 | 레벨마다 | 해금 레벨, 숨기기, 레벨 수(Z-5) |
| 생산기 | 이름 | 그림 하나 (+레벨 숫자) | 내는 계열 (Z-6) |
| 주민 | 이름 | 그림 | 좋아하는 계열, 입주 레벨, 숨기기 |
| 클리커 | — | 그림 | — |
| 상자·거미줄·🎁 | — | 그림 | — |

- **Z-3 되돌리기** — 항목마다 [기본값으로]. 전부 되돌리기도 있다.
- **Z-4 숨기기** — 계열·주민은 지우지 않고 **숨긴다**. 숨긴 계열은 생산기가 더 내지 않고 주문에도 안 나오지만,
  이미 보드에 있는 아이템은 그대로 쓰고 합칠 수 있다. 숨긴 주민은 주문하지 않는다. (지우면 보드에 정체를 모르는 아이템이 남는다.)
- **Z-5 새 계열 만들기** — 이름, 레벨 수(3~12) 〔custom.minLevels〕〔custom.maxLevels〕, 레벨마다 이름·그림,
  내는 생산기, 좋아하는 주민, 해금 레벨. 만든 계열의 레벨 수는 **늘릴 수만** 있다 —
  줄이려면 그 계열의 넘치는 레벨 아이템이 보드·보관함·주문에 없어야 한다 (있으면 몇 개가 어디 있는지 알려 준다).
- **Z-6 생산기와 계열 잇기** — 생산기마다 내는 계열을 체크한다. 아무것도 안 내는 생산기는 클릭해도 ⚡ 를 쓰지 않고 "도감에서 계열을 연결하세요".
- **Z-7 새 주민 만들기** — 이름·그림·좋아하는 계열·입주 레벨.
- **Z-8** 꾸민 외형은 **내 화면에만** 있다. 친구에게 가는 것은 할 일과 점수뿐이다 (P-3).
- **Z-9** 계열·주민·생산기 수에는 제한을 두지 않지만, 주문 칸·보드 크기는 그대로다.

## 15. 점수와 친구 공유

- **P-1 점수** = ⭐. 친구 목록은 **이번 주 ⭐** 로 정렬하고 누적 ⭐ 와 레벨을 함께 보인다. 이번 주는 T-2 와 같은 기준.
- **P-2 공유되는 것 (이것뿐)**: 이름 · 레벨 · 누적 ⭐ · 이번 주 ⭐ · 연속 달성 일수 ·
  오늘의 일간 할 일 (내용·완료·크기·목표 횟수 진행) · 이번 주 주간 할 일. 비공개 할 일은 내용이 아예 실리지 않는다.
- **P-3 공유되지 않는 것**: 보드, 보관함, 에너지, 에너지 기록, 꾸민 외형, 지난 기간의 할 일.
- **P-4 전달**
  1. 처음 한 번 **친구 코드**를 서로 주고받는다 (둘 다 추가해야 친구).
  2. 그 뒤로는 **iroh 자동 동기화** — 둘 다 켜져 있을 때 저절로, 서로 친구인 제3자가 대신 전해 주기도 한다 ([MERGE_GAME.md §6](MERGE_GAME.md#6-자동-동기화-p3--iroh)).
  3. 동기화를 껐거나 급하면 **상태 코드**를 메신저에 붙여넣는다.
- **P-5** 친구 카드에는 언제 받은 상태인지 보인다. 친구의 "오늘" 이 내 오늘과 다르면 "어제 기준" 으로 표시.
- **P-6** 친구에게는 **보기만** 한다.
- **P-7** ⭐ 는 클리커로 얻은 ⚡ 로도 쌓인다 — 즉 ⭐ 는 "할 일을 얼마나 했나" 의 정확한 척도가 아니다.
  할 일 달성 현황은 따로 보이므로(P-2) 친구는 둘을 함께 본다. ✏️ 순위를 할 일 달성률로 매기고 싶으면 정렬 기준만 바꾸면 된다.

## 17. 더해 가는 법

처음부터 다 만들지 않고 늘려 갈 것이므로, 무엇을 더할 때 **어디만 건드리면 되는지**를 정해 둔다.

| 더하고 싶은 것 | 건드리는 곳 | 예 |
|---|---|---|
| 숫자 조정 | `merge-economy.json` 키 하나 (또는 덮어쓰기 파일) | 회복 간격 90초 |
| 계열·주민·외형 | 도감(사용자) 또는 기본 콘텐츠 `merge-content.json` | 새 계열 "문구" |
| 새 **에너지 출처** | 에너지 기록에 출처 이름 하나 + 지급 함수 하나 | 출석 보너스, 친구 응원 |
| 새 **에너지 쓰임** | 같은 방식 (출처 이름이 `spend:*`) | 생산기 강화 |
| 새 **특수 아이템** | 아이템 종류 목록에 하나 + "클릭하면" 처리 함수 하나 | 🃏 만능 조각, ⏩ 생산기 즉시 2배 |
| 새 **칸 상태** | 칸 상태 목록에 하나 + 열림 규칙 | 🧊 얼음 (합성 2번에 녹음) |
| 새 **탭/미니게임** | 위젯 탭 하나 + 필요하면 에너지 출처 하나 | 클리커 옆 슬롯머신 |
| 친구에게 보일 것 | 상태 스냅샷에 필드 하나 (버전 올림, 옛 앱은 모르는 필드를 무시) | 이번 주 클리커 횟수 |

원칙: **에너지는 기록(장부)을 거쳐서만 늘고 준다.** 새 출처·쓰임이 몇 개가 되든 "지금 ⚡ 가 왜 이만큼인가" 는 기록으로 설명된다.

## 18. 튜토리얼과 힌트

  1. "🧰 를 눌러 보세요" → 🫧 생산
  2. "🫧 두 개를 겹쳐 보세요" → 🧼 (이웃 상자가 열린다)
