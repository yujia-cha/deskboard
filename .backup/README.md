# 보관본

git 저장소가 아니라 되돌릴 안전망이 없어 손으로 남긴다.

## `window.rs.owner-persistent`

Win+D(바탕화면 보기) 대응으로 **바탕화면 창을 이 창의 소유자로 상시 지정**하는 판.
2026-09-21 실기 확인 결과:

- Win+D 로 바탕화면을 봐도 **위젯이 남는다** (OK)
- 한 번 더 누르면 앱이 복원되고 대시보드가 **뒤로 내려간다** (OK)
- **빈 바탕화면 클릭·아이콘 표시 정상** (OK)
- 남은 문제: 소유 관계가 활성화를 가로채, 그 뒤 **한/영 전환이 바로 되지 않는다**.
  작업 표시줄을 한 번 클릭하면 풀린다. (Windows 는 소유자가 활성화되면 그 그룹의
  마지막 활성 팝업으로 활성화를 넘긴다 — 전경이 `Progman ↔ Tauri Window` 로 진동한다.)

## 되돌리는 법

```
cp .backup/window.rs.owner-persistent src-tauri/src/window.rs
```

## 시도했다가 더 나빴던 것 (되살리지 말 것)

- `WS_EX_TOOLWINDOW` + `WS_EX_APPWINDOW` 제거 — 활성화 가로채기를 **막지 못했다**.
- 소유 관계를 "바탕화면 보기" 동안에만 걸고 `WS_EX_NOACTIVATE` 를 함께 켜기 —
  탐지가 늦어 **Win+D 때 위젯이 아예 보이지 않고**, 복원 때 앱 위에 잠깐 떴다 사라졌다.
  상시 소유보다 명백히 나빴다.

자세한 실측은 `src-tauri/src/window.rs` 의 "Win+D 에서 살아남기" 머리말 참고.
